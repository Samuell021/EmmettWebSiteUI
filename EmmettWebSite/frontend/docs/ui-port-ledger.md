# دفترچهٔ پورت «UI» → فرانت‌اند Next.js

این سند، «دفتر کل» پورت ۱:۱ بستهٔ طراحی `UI/` (خروجی Figma Make) به فرانت‌اند Next.js
(``EmmettWebSite/frontend/``) است: چه چیزی منتقل شده، چه چیزی عمداً منتقل نشده و چرا، و
چه چیزهایی برای فازهای بعد باز مانده است.

## قواعد ثابت این پورت

1. **بک‌اند (Django/DRF) صفر تغییر** — نه مدل، نه ویو، نه مهاجرت. هر جایی که بک‌اند
   کمبود داشته باشد، مسئله در سمت فرانت حل می‌شود.
2. **ظاهر پورت‌شده مو‌به‌مو همان UI است** — کلاس‌ها، هگزها، فاصله‌ها و موشن‌ها بدون
   تغییر. تبدیل‌های مجاز علاوه بر ``to=`` → ``href=``، ``"use client"`` و
   ``react-router`` → ``@/i18n/navigation``، در بخش فاز ۲ فهرست شده‌اند.
3. **دو زبانه (fa/en) و کاملاً داینامیک** — محتوای هر بخش از API بک‌اند می‌آید
   (``Accept-Language``)، متن هاردکد UI فقط fallback است.
4. **آزمون پذیرش بصری** — پس از هر فاز، مقایسهٔ خروجی build با حالت قبل؛ حذف/تغییر
   هر قاعدهٔ CSS موجود ممنوع است.

### الف) فایل‌های CSS بستهٔ UI (۶ فایل، ۱۰۰٪ ردیابی‌شده)

### ب) توکن‌ها و «چرا scoped؟»

در فاز ۱ مقادیر UI زیر کلاس ``.ui-theme`` تعریف شده‌اند (نه در ``:root``)، به دو دلیل:

1. باید **هیچ‌چیز از UI جا نیفتد**: همهٔ ۴۸ توکن با همان نام‌ها/مقادیر + کل لایهٔ base،
   زیرمجموعهٔ ``.dark`` (که مقادیرش با ``:root`` مو‌به‌مو یکی است — با ابزار بررسی شد:
   ۳۴ کلید مشترک، صفر تفاوت)، و قاعده‌های ``h1..h4/label/button/input``.
2. باید **مسیرهای فعلی هیچ تغییر بصری نگیرند**: ۱۸ مسیر فعال هنوز با دیزاین‌سیستم
   قبلی (ADR-0017) کار می‌کنند و بازطراحی‌شان فاز ۷ است.

سازوکار فنی: نگاشت‌های ``@theme inline`` در ``globals.css`` هر کلاس معنایی را به
متغیر زنده تبدیل کرده‌اند (``.bg-background → background-color: var(--background)``،
``.rounded-lg → border-radius: var(--radius-value-lg)``، ``.border-border → border-color:
var(--border)``). پس هر عنصر داخل ``.ui-theme`` خودکار مقدار درست UI را می‌گیرد —
**بدون تغییر حتی یک کلاس در کد پورت‌شده**. این ادعا در خروجی build راستی‌آزمایی شد.

نکتهٔ حیاتی گردی‌ها: UI برای ``rounded-md`` و ``rounded-lg`` مقادیر ۶px و ۸px دارد اما
دیزاین‌سیستم فعلی ۸px و ۱۶px؛ به همین دلیل ``--radius-value-sm/md/lg`` داخل `.ui-theme`
بازتعریف شد تا ``rounded-md``/``rounded-lg`` در ناحیهٔ پورت مو‌به‌مو مثل UI شوند.

## تصمیم‌های ثبت‌شدهٔ مالک محصول (پیش از فاز ۲)

1. **بریک‌پوینت‌ها — وفاداری کامل به UI با تضمین رسپانسیو بودن.** مقیاس بریک‌پوینت فرانت
   به پیش‌فرض Tailwind (همان مقیاس UI: sm=640، md=768، lg=1024، xl=1280، 2xl=1536)
   برمی‌گردد تا پورت Home مو‌به‌مو باشد. چون این تغییر مقیاس، رفتار عرض‌های میانی
   مسیرهای فعلی را هم تغییر می‌دهد، در فاز ۲ پیش از پورت:
   - فهرست کامل کاربردهای `sm/md/lg/xl` در ۱۸ مسیر فعلی استخراج و در عرض‌های مرزی
     (۳۲۰، ۳۹۰، ۶۴۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۴۴۰، ۱۹۲۰) بازبینی می‌شود؛
   - هر نقطهٔ شکست احتمالی (چیدمان‌های وابسته به px دقیق) اصلاح و مستند می‌شود؛
   - تأیید نهایی روی پیش‌نمایش زنده در همین عرض‌ها (چون دانلود مرورگر Playwright در
     محیط فعلی ممکن نیست، بازبینی بصری به‌صورت دستی/پیش‌نمایش انجام می‌شود).
2. **حالت روشن/تیره — تک‌حالت تیره، دقیقاً مثل UI.** دکمهٔ تغییر تم (`ThemeToggle`)
   در فاز ۷ (بازطراحی مسیرهای فعلی) حذف می‌شود؛ تا آن زمان دست‌نخورده می‌ماند تا در
   مسیرهای فعلی تغییر بصری ناخواسته رخ ندهد. توکن‌های UI طوری نگه داشته می‌شوند که
   افزودن پالت روشن در آینده (در صورت نیاز) بدون بازنویسی ممکن باشد.

## فاز ۲ — گزارش کامل

### الف) چه چیزی پورت شد

۱۳ فایل زنده (۱۱ کامپوننت Home + `Home` + `ComingSoon`) در
``src/components/ui-port/``، با پوستهٔ ``(ui)`` روی ``/`` و دو مسیر جدیدی که در فرانت
نبودند: ``/products/pentestor`` و ``/products/crm``. ۱۸ مسیر قبلی به گروه ``(site)``
جابه‌جا شدند و پوستهٔ خودشان (هدر/فوتر ADR-0017) را حفظ کردند. بک‌اند تغییر نکرد.

تبدیل‌های مجاز این فاز، غیر از سه تبدیل مکانیکی فاز ۱:

- برچسب ناوبری از ``nav.*`` (en مو‌به‌مو همان رشتهٔ UI؛ fa برچسب موجود سایت).
- ``left/right/ml/pr`` فیزیکی → ``start/end/ms/pe`` تا fa (RTL) آینه شود و en مثل UI بماند.
- ``/library`` → ``/blog`` (قرارداد URL بک‌اند؛ تست موجود «کتابخانه → /blog»).
- ``NeuralNetwork3D`` با ``next/dynamic`` و ``ssr: false`` (three.js در باندل اولیه نیاید).
- لودر: محتوا زیر پوشش مات رندر می‌شود (SEO / بدون JS) و با ``prefers-reduced-motion``
  پنهان می‌شود. کلید ``sessionStorage`` ندارد.
- لینک پرش به محتوا و ``<main>`` — فقط برای کیبورد / لندمارک؛ روی ظاهر اشاره‌گر اثری نیست.

عمداً منتقل نشد: کامپوننت‌های مردهٔ UI (در ``App.tsx`` رندر نمی‌شوند) و ۹ مسیر ComingSoon
دیگر (فاز ۵). متن بدنهٔ هوم انگلیسی ماند (۱:۱ با UI). ⌘K هنوز فهرست ثابت است (فاز ۴).

### ب) بازبینی عرض‌های مرزی (استاتیک)

مقیاس: sm ‏۷۶۸→۶۴۰، md ‏۱۰۲۴→۷۶۸، lg ‏۱۲۸۰→۱۰۲۴، xl ‏۱۴۴۰→۱۲۸۰. ``xxs``/``xs``/``2xl``
دست نخوردند. مرورگر Playwright در این محیط نیست؛ بازبینی روی همهٔ کلاس‌های
``sm/md/lg/xl`` مسیرهای فعلی و اندازه‌گیری عرض فونت Vazirmatn (وزن ۷۰۰ به‌عنوان سقف) بود.
عرض‌های ۳۲۰ و ۳۹۰ زیر همهٔ بریک‌پوینت‌ها هستند و نسبت به قبل عوض نشدند.

| نقطه | حکم | کار |
| --- | --- | --- |
| هدر، نوار ۹لینکی fa | سرریز. ردیف حدود ۱۲۳۸px است. ``md:flex`` با مقیاس جدید از ۷۶۸ باز می‌شد؛ حتی ۱۰۲۴ هم جا نمی‌شود. از ۱۴۴۰ به بعد، با padding مربوط به ``lg``، حدود ۱۲۲px اضافه می‌ماند. | نوار دسکتاپ از ``min-[90rem]:`` (۱۴۴۰). زیر آن همبرگر. |
| ``max-w-(--breakpoint-xl)`` | این کلاس عرض ظرف را به توکن xl وصل کرده بود. با برگشت xl به ۸۰rem، measure همهٔ صفحات در ۱۴۴۰+ از ۱۴۴۰ به ۱۲۸۰ باریک می‌شد و هدر حتی در ۱۹۲۰ جا نمی‌شد. | توکن جدا ``--container-site: 90rem`` در ۱۰ جای مسیرهای فعلی. پورت UI از ``max-w-[1440px]`` لفظی استفاده می‌کند و اثری نگرفت. |
| گریدهای ``sm:grid-cols-2/3``، ``lg:grid-cols-3/4``، سواچ ``md:grid-cols-5`` | متن می‌شکند؛ ``nowrap`` یا ``min-width`` ثابت ندارند. سرریز صفحه ندارند. زودتر چندستونه شدن، باگ نیست. | بدون تغییر. |
| Hero ``md:flex-row`` + ``text-6xl`` | از ۷۶۸ (به‌جای ۱۰۲۴) دوتکه می‌شود. بلندترین واژه در ستون ۷/۱۲ جا می‌شود. تصویر ``w-full`` است. | بدون تغییر. |
| ``lg:px-10`` | padding از ۱۰۲۴ به‌جای ۱۲۸۰. ۱۶px تو رفتگی بیشتر. سرریز نمی‌سازد. | بدون تغییر. |
| درس آکادمی با ``whitespace-nowrap`` | در ۳۲۰ می‌تواند تنگ شود، ولی هیچ کلاسی از مقیاس جدید آنجا اثر ندارد (قبل و بعد یکی است). | به فاز ۷ موکول شد. |

تأیید پیکسلی روی پیش‌نمایش زنده هنوز باز است — محیط مرورگر ندارد.

### ج) برابری مسیرهای فعلی

HTML بیلد فاز ۱ و بیلد فاز ۲ برای ۱۵ مسیر قدیمی (غیر از ``/`` و ``/en`` که عمداً عوض
شده‌اند)، بعد از حذف اسکریپت: ۱۳ مسیر بایت‌به‌بایت یکی. ``design-system`` فقط ``useId`` و
ساعت زنده فرق دارد. ``/products`` فقط جای متادیتای استریم‌شدهٔ Next فرق دارد (بدنه یکی است).
هیچ متغیر CSS قدیمی حذف نشد. ``.shrink-0`` در CSS جدید هست (با ``.flex-shrink-0`` ادغام شده).

### د) focus و پورتال

- بستهٔ UI قاعدهٔ focus ندارد. حلقهٔ ``:focus-visible`` سراسری فرانت داخل ``.ui-theme`` هم
  اعمال می‌شود و فقط با کیبورد دیده می‌شود. حذفش معیار دسترس‌پذیری پروژه را می‌شکند؛ ماند.
- پالت ⌘K داخل درخت ``.ui-theme`` است، نه Portal. خطر پورتال برای این فاز مصداق نداشت.

## فاز ۳ — اتصال دادهٔ Home

متن آیتم‌ها از فهرست‌های موجود می‌آید: ``/services/``، ``/projects/?is_product=true``،
``/projects/``، ``/blog/``، ``/academy/``. سقف نمایش همان طراحی است (۵ / ۳ / ۳ / ۵ / ۳).
عنوان ثابت بخش‌ها، تگ‌ها، داشبورد داخل کارت محصول، پشته و نتیجهٔ پروژه، دستهٔ مقاله،
برچسب گره‌های آکادمی و دکمهٔ تماس خانه دست نخورده‌اند — این‌ها فیلد فهرست نیستند.
اگر اندپوینت در دسترس نباشد، همان متن طراحی می‌ماند. ``POST /leads/contact/`` از قبل
روی ``/contact`` است و به خانه منتقل نشده. بک‌اند تغییر نکرده.
